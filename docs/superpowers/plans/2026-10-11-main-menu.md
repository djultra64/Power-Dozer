# Original-style main menu implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show the approved three-entry main menu before original file selection,
with complete pre-game PC settings and the original background/ticker.

**Architecture:** Reuse the ROM-decoded assets and existing RT64 presentation
hook. Give the frontend an explicit host screen state and give PC settings an
entry/return context; verified guest hooks retain save/erase logic while SDL owns
host events and rendering consumes one immutable screen snapshot per frame.

**Tech Stack:** C++20, SDL2, N64Recomp/N64ModernRuntime, RT64/Plume, HLSL,
CTest and Python unittest. Existing private ROM/code/dependency setup is retained.

**Spec:** docs/superpowers/specs/2026-10-11-main-menu-design.md (user approved).

## Global Constraints

- Project attribution: djultra64; verify both Git identities before commit/publication.
- Reuse actual game font, colors, shadows, animated background and bottom ticker.
- Exactly Start Game, PC Options, Close Game; heading POWER DOZER.
- Original title/attract and original file/name/erase flows remain intact.
- Back on main is inert; file-selector Back returns main; options Back returns its origin.
- Keep all settings rows visible and physical Xbox/PlayStation/Switch prompts correct.
- Preserve held-input suppression, remapping, manual family fallback and centered stick arrows.
- Guest hooks own guest RAM; SDL owns input/exit; render hooks read immutable value data.
- No shared dependency source edits, ROM pixels, private generated game code or saves in commits/packages.
- Close Game uses existing window-close main-loop path; no new coordinated-worker shutdown claim.
- Shadow-border and ticker-medal fixes are independent tracks; this menu does not waive their native acceptance.

## Review Focus

- A disconnected or changed active controller must not leave invisible host selection or stale prompts (Task 3).
- Initial file setup and return from erase/name dialogs must not accidentally reopen main (Task 3).
- Holding Confirm across transitions must not select a file, reset settings or trigger Close Game (Task 3).
- Failed settings saves and fixed Escape recovery must return to the correct menu context (Tasks 1/3).
- Alt+Enter/resize during main/options must preserve ownership, original ticker and mouse targets (Tasks 2/4).

## File responsibilities

New include/main_menu.h and src/main_menu.cpp contain frontend menu state,
requests and value snapshots. Existing pc_settings_view/input files add explicit
settings origin. pc_settings_renderer.cpp reuses its builder/assets for the main
view; it does not create another GPU atlas/lifecycle. New src/frontend_menu.cpp
and include/frontend_menu.h contain SDL/guest transition adapters. Verified
hooks belong in tools/recompile.py; main/input/pc_options integrate adapters.
Focused tests mirror these responsibilities. Native tools/docs are updated only
after integration. Execute tasks sequentially because renderer/input/guest contracts
are shared; reviews are independent.
